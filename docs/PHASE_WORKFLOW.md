# Phase 진행 워크플로 (연속 자동 모드 — 실험용)

> ⚠️ 실험 모드: 사용자 확인 없이 **Phase 1부터 7까지 연속으로** 설계→구현→검토를 자동 수행하고, 한 Phase가 끝나면 **스스로 다음 Phase로 넘어간다.** 중간 게이트가 없어 완성도는 단계별 확인보다 낮을 수 있다. "초안/실험" 목적으로 사용한다.

## 사용자가 "남은 Phase 다 자동으로 해줘" 라고 하면

`docs/PRD.md` 의 Phase 로드맵을 순서대로, **현재 미완료 Phase부터 마지막 Phase까지 연속으로** 자동 수행한다.

### 시작 시 1회

1. CLAUDE.md, docs/PRD.md, docs/TODO.md, docs/FSD.md, docs/UIUX.md, design/DESIGN.md 를 읽는다.
2. docs/TODO.md 가 없으면 PRD 로드맵 기반으로 생성한다.
3. 기존 산출물을 점검해 **어느 Phase부터 시작할지** 판단하고, 그 지점부터 진행한다.

### 각 Phase 루프 (Phase 끝날 때마다 자동 반복)

1. **설계 (planner/critic)**: 해당 Phase 계획 — FSD 레이어 배치 + 데이터 흐름(app→hooks→repository) + 핵심 기술 결정 + UI/UX 적용 지점.
2. **구현 (executor/designer)**: 계획대로 구현. UI 비중 큰 부분은 designer 활용.
3. **검토 (ultraqa/code-review)**: 완료 기준·FSD 위반·토큰 하드코딩·UX·엣지케이스 점검 후 그 자리에서 수정. 완료 기준을 충족할 때까지 반복.
4. **기록**: docs/TODO.md 에 해당 Phase 완료 표시 + 변경 요약을 남긴다.
5. **커밋 (자동)**: 그 Phase 변경분을 git 에 커밋한다. (아래 "자동 커밋 규칙" 참고)
6. **다음 Phase로 자동 진행**: 멈추지 말고 다음 Phase의 1번부터 이어서 수행한다. **모든 Phase가 끝날 때까지 멈추지 않는다.** (ralph 지속 모드처럼 끝까지 간다)

### 전부 끝나면

- Phase 1~7 전체 완료 보고: Phase별 결과 요약 + 완료 기준 충족 여부 + 알려진 이슈 목록 + Phase별 커밋 목록.
- docs/TODO.md 최종 갱신.

## 자동 커밋 규칙

각 Phase가 완료 기준을 충족하고 docs/TODO.md 를 갱신한 직후, 그 Phase 작업분을 커밋한다.

**브랜치 전략 (중요)**

- 개발 = `dev`, 운영 = `main`.
- **모든 자동 커밋은 `dev` 브랜치에만 한다. `main` 은 절대 건드리지 않는다.**
- 시작 시 현재 브랜치가 `dev` 가 아니면 `dev` 로 전환한다. `dev` 가 없으면 `main`(또는 현재 브랜치) 기준으로 `dev` 를 만들어 거기서 작업한다.
- `dev` → `main` 머지는 **자동으로 하지 않는다.** 사용자가 Phase들을 확인한 뒤 직접 한다.

**커밋 규칙**

- **시점**: Phase별로 1커밋. 검토까지 끝나 "동작하는 상태"에서 커밋한다. (어중간한 중간 상태로 커밋하지 않는다)
- **대상**: 그 Phase에서 변경/추가된 파일. `git add -A` 후 커밋.
- **메시지 형식 (통일)**: `feat: Phase {N} - {Phase 이름}`
    - 예: `feat: Phase 1 - 도형 편집기 코어`
    - 본문(선택)에 핵심 변경 요약을 2~4줄 불릿으로 남겨도 된다.
- **로컬 커밋만**: `git push` 는 하지 않는다. (원격 연동·푸시는 사용자가 직접 한다)
- **실패 처리**: 커밋이 실패해도(예: git 미초기화, 충돌) 전체 흐름을 멈추지 말고, 그 사실을 보고에 남긴 뒤 다음 Phase를 계속 진행한다.
- git 저장소가 아직 초기화돼 있지 않으면, 첫 커밋 전에 `git init` 후 `dev` 브랜치를 만들어(원격 설정은 하지 않음) 진행한다.

## 모든 Phase에서 반드시 지킬 것

- **FSD(docs/FSD.md)**: 라우트·컴포넌트는 repository 직접 호출 금지(features/<domain>/hooks 경유), repository는 default export, 역방향 의존 금지.
- **디자인 토큰**: 색·간격·폰트·라운드는 @shared/theme 토큰만, 하드코딩 금지.
- **UI/UX(docs/UIUX.md)**: 사용성 우선 + 부드러운 UX. 의미 있는 전환에 짧고 부드러운 모션(ease-out 150~300ms), 누르면 즉각 피드백. 빈 상태/로딩/에러 처리, 터치 타겟 44dp+.
- **패키지**: 추가 시 이유 한 줄 설명. pnpm 고정(npm·yarn·npx 금지).

## 연속 자동이라도 멈춰서 물어볼 것 (유일한 예외)

- **데이터 모델(Project/Shape/Material 구조)을 바꿔야 할 때** → 자동 진행을 멈추고 사용자에게 묻는다. (이건 잘못 가면 전체가 무너지므로 끝까지 자동화하지 않는다.)
- 그 외 되돌리기 어려운 핵심 기술 결정(예: 도형 SVG vs View)은 **멈추지 말고 자동 결정하되, 선택 이유를 그 Phase 보고에 명시**한다.

## 끝난 뒤 (사용자 몫)

전체 자동 실행이라 버그가 누적됐을 수 있다. 사용자는 Phase별로 앱을 점검하고, 문제가 있으면 해당 Phase만 다시 보완 요청한다.
